# Copy approvals — decision D22 (design batches 3–12)

**Date:** 2026-11-08. **Decided by:** Main, on the owner's delegation (see `OWNER-DECISIONS.md`), after an independent reviewer-claude audit of every proposed string against `BRIEF.md` A0, A11, A17 and the source.
**Scope:** the "Proposed copy" lists in the batch 3–12 conflict sheets: B3 G10; B4 G12 and the G16–G19 sentences; B5 G17; B6 G12, G13, G14; B7 G7; B8 G6; B9 G4 and G7; B10 G4 (sections A, B, C); B11 G4 (sections A, B, C); B12 G4. 288 strings were reviewed: 215 are approved as proposed and 73 are listed below. Approval is wording only: it does not commit the feature that uses a string.
**Not product copy (skipped):** specimen labels and annotations such as "Render state, not A18 data", "Contract-derived render state, not A18 data", "Structural placeholder: …", "structural, not data: …", square-bracket placeholders ([N], [P], [JSON engine message …], [browser validation text], [not supplied: structural]), canvas notes, and cloud slot names.
**Fixture values in approved strings are templates:** period 801 becomes {id}; tariff 301 becomes {tariff name} ({id}); dates and times become {range} and {time}; "Asia/Kuala_Lumpur (UTC+08:00)" becomes {siteTimezone} (UTC{offset}); a 100-event page becomes the request's page size.

## Cross-batch rules (apply to every string, including strings not listed)

- Specimen labels and annotations are skipped and not counted as product copy. Examples: "Contract-derived render state, not A18 data", "Render state, not A18 data", "Brief-required state (A12.5), not A18 data", the [N]/[P] pager placeholders, "Presentation backlog wording: “Role not verified”", "rows not drawn: category data is batches 8 to 10", Prerequisite-blocked canvas notes, "Owning request: …" and "…: static, no shimmer" notes, "First page: Previous is disabled."-style pager annotations, frame captions, and the B7 withdrawn strings.
- Fixture values in approved strings are templates: period 801 → {id}, tariff 301 → {tariff name} ({id}), dates/times → {range}/{time}, Asia/Kuala_Lumpur (UTC+08:00) → {siteTimezone} (UTC{offset}), 100-event page → the request's page size.
- Product copy never contains these words: A18, fixture, variant, baseline, hypothetical, proposed, specimen, "rows not drawn". Any string that does is rejected or edited.
- No GraphQL operation names (PowerSeries, EnergyTotals, …) and no "cursor" in visible copy. Raw status and reason codes (UNAVAILABLE, NO_READING, MAPPING_PROVISIONAL, VENDOR_DATA_ONLY) stay visible as A17 requires.
- How to show missing data. A nullable field the API returned null is "—" with its returned reason (models.ts:15,24,42,92-95). A null lastError or empty investigation path is "None" (DataQuality.tsx:170,506). "Not supplied" is only for a field the API does not provide for that item (power-point provenance, flags or gap reason; per-window coverage). A non-null schema field (acquisitionSource, freshness, effectiveFrom, investigationPath) must never read "not supplied".
- Retry, Refreshing and "… unavailable" strings reuse the region noun of the Current loading message: daily totals (Overview.tsx:247), energy totals (History.tsx:335; UsageCost.tsx:254), collector status, devices, policies, quality events, daily comparison(s), meter readings, calculation runs, billing periods, tariffs.
- Where a Current or brief string already covers a state, reuse it verbatim. Covered states: A17 current-day partial ("Today so far · through {time}. Coverage {coverage} of the requested local day."); "Not calculated"; "Recalculation pending"; "No SOC values were recorded in this range."; "Average SOC is not available at this resolution"; "Select two different readings for reconciliation."; "No window breakdown".
- Copy never recomputes coverage from on-screen counts (e.g. 670 of 672 h = 99.7%). It shows the coverage the backend returned (A17).
- "Recalculation pending" copy describes only what the stale flag means: derived results were marked stale when a recalculation was requested (accounting.mutations.ts:240-243). It never implies the bill was recalculated or that the app recalculates.
- Approval is wording only. "Request recalculation" and "Recalculation requested" (B5) are acceptable wording but stay subject to D06 (prerequisite-blocked). "No daily rows in this range." (B6) is acceptable wording but subject to D07.
- Ambiguous mutation outcome (B9, B10, B11): start with the A18.5/A17 sentence "Could not confirm the change." and follow it with one operation-specific consequence that the backend actually guarantees. Do not use "Outcome unknown: the client cannot know…", GraphQL operation or query names, or "returns false". Never state or imply that nothing was saved, or that anything was rolled back.
- Recovery steps and disabled reasons name the visible list or control ("Refresh billing periods", "Refresh readings"), not query names. Save or Delete is re-offered only after a refresh that succeeds ("have been refreshed" / "after the refresh succeeds"). Do not use annotation words such as "Later step:" or "today" in product copy.
- "Drafts are kept. The forms return when ADMIN access is confirmed." replaces the proposed role-verified wording in every batch, matching the existing notice at Settings.tsx:418.
- Recalculation copy says 'marked for recalculation', 'needing recalculation' or 'Recalculation pending' (A17). Never say totals or bills 'are recalculated': the mutations only queue a ledgerDirtyRange (accounting.mutations.ts:91-100, 110-119) or change counts (policy.ts:275-302).
- The A11 pager strings ("Showing [N] readings · more available", "All [N] readings loaded", "Loading more…", "Refresh readings") replace the Current strings in the shared MeterReadingsPager (components/Display.tsx:80-94), which Data Quality also renders. Never show both wordings. Use the singular for N=1. In the same change, update the "Loading readings…" assertions at api.spec.tsx:121, connection.spec.tsx:96 and SettingsReadings.spec.tsx:243.
- The "Unverified" badge replaces the inline lowercase "unverified" (Settings.tsx:475) rather than appearing beside it. "bill verified" is unchanged, and no badge ever says Verified for a fixture tariff (A12.4).
- Timestamps in sentences follow A17: "D Mon YYYY, HH:MM:SS", plus zone and offset where a zone is shown.
- Specimen labels were skipped and not audited as product copy: square-bracket placeholders ([N], [request error message], [JSON engine message …], [DateTime scalar …], [not supplied: structural], [browser validation text], etc.), "Structural placeholder(s)", "structural, not data: …", "illustrative (A18 fixture ID …)", "Source Not supplied", the cloud slot names, and 'Render state, not A18 data'. Fixture values inside approved strings (#1201, #902, 2026, demo-admin, Asia/Kuala_Lumpur) are substituted at runtime.
