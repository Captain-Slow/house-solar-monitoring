## Source and common interpretation

Register source: [hoymiles-g3-modbus-tcp at 78c620d](https://github.com/zhongfu/hoymiles-g3-modbus-tcp/tree/78c620dfe01849e7610d84b64823dd958c901476), map version `hoymiles-g3-modbus-tcp@78c620d+1` in `apps/backend/src/modbus/register-map.ts`. Source/license attribution is retained there. FC04 is used unless a row explicitly says FC03; no write function is available.

Timestamps are collector `observedAt` (poll midpoint), never inverter-clock time. All hardware cadence entries are **not measured**. A 10-second configured polling interval is not evidence of a 10-second device update cadence.

Grid netting semantics are a software contract, not verified physical accuracy. `METER_NET` integrates the normalized external-meter **total** (`meter_active_total`, register 1814, stored as `Sample.gridW` after the mapping's `gridMeterSign`) and splits import and export directionally for each integration interval. `METER_PER_PHASE` splits each normalized phase power (1808/1810/1812, stored as `Sample.gridAW/BW/CW` after `gridMeterPhaseSign`) directionally for each interval and sums the per-phase import and export results. Both candidates are always stored (`gridImportNetWh`/`gridExportNetWh` and `gridImportPhaseWh`/`gridExportPhaseWh`) and can differ, because phases may carry opposite flow and the reported total need not equal the phase sum. `METER_NET` is never derived from the phases: when the total is unknown or invalid for an interval, that interval is unknown for `METER_NET` (a grid gap) even if all three phases are valid; `METER_PER_PHASE` likewise needs all three phases and never falls back to the total. `METER_PER_PHASE` has its own coverage column, `gridPhaseCoveredSec` (migration `0006_grid_phase_coverage`): the seconds in which all three normalized phases were valid, which is exactly the time `gridImportPhaseWh`/`gridExportPhaseWh` integrate (the minimum over the phases, never a sum). `gridCoveredSec` stays the meter-total coverage; totals, reconciliation and billing use the coverage of the active grid candidate (`METER_NET` uses `gridCoveredSec`, `METER_PER_PHASE` uses `gridPhaseCoveredSec`, `INVERTER_COUNTER` its counter coverage). With the total missing and all three phases valid, `METER_PER_PHASE` therefore reads full coverage while `METER_NET` reads 0 s; with the total valid and a phase missing it is the other way round. `gridPhaseCoveredSec` is NULL for rows stored before the migration (phase coverage unknown, not zero): readers fall back to `gridCoveredSec` for those rows, exactly as before, until ordinary ledger recomputation rewrites a bucket from retained Sample evidence. The ledger algorithm version is unchanged and no historical row is recomputed because of this column. The shared `GRID_GAP` flag is still raised by a gap in the total or in any phase, so a bucket can carry it while the active candidate had no gap. Grid power series and statistics (`gridAvgW` and friends) remain meter-total based. Derived household load uses the same meter total. Signs, CT location, meter update cadence and which candidate matches the utility remain PROVISIONAL until G3, G5 and G6 produce site evidence; G6 compares both candidates with TNB meter deltas and the active source stays an explicit admin policy decision.

Uncertainty for integrated energy: CT/meter class and installation error are unknown; sampling error awaits G4/G5; power quantization is 1 W. Do not claim class-1 accuracy from a typical meter specification. Counter resolution is 0.1 kWh (100 Wh); its underlying instrument and physical meaning await G5/G6. Derived load inherits all input errors. Vendor summaries are unvalidated comparison-only values, not measured utility totals.

Battery power is read from `bat1_power_g3` 50 (block 0, mapping source `BAT1_POWER_G3_50`) or `batt_power_bms` 1914 (block 1800, `BMS_1914`) according to the mapping version a sample was normalized with. In the ledger and in power series only the selected source's block flag (`BLOCK_INVALID_0` or `BLOCK_INVALID_1800`) or `CLOCK_STEP` masks battery power; the other block failing leaves it intact. SOC (1909) follows block 1800 independently of either power source. Its coverage counts distinct valid occupied ten-second observation slots, not integrated battery-power time. Coarse SOC has no manufactured average: it reports extrema and independent `socCoveredSec`. A historical NULL coverage value means the required evidence was not reconstructed, not zero SOC or full coverage.

Power integration uses exact millisecond interval lengths. Wh is rounded to three decimal places only when persisted as `Decimal(12,3)`. Totals sum those persisted fractional Wh as Decimal before converting to kWh; `energyTotals` rounds its final kWh output once to three decimal places, not each bucket before summation. Integrated covered seconds are separate whole-second metadata, floored after snapping floating-point summation noise to the millisecond grid. Flooring coverage does not truncate energy.

For a partially queried historical SOC bucket, the persisted occupied-slot count does not identify slot positions. Coverage is the conservative intersection lower bound `max(0, queriedSeconds - (300 - socCoveredSec))`, not `min(queriedSeconds, socCoveredSec)`. Full-bucket coverage is unchanged; 300 known covered seconds still prove full coverage of any subwindow. Min/max remain whole-bucket extrema and `avg` stays NULL.

Ledger algorithm version 3 makes bucket mapping attribution independent of replay extent and persists independent SOC coverage. Its upgrade worker uses **`SAMPLE_RETENTION_DAYS`**, not raw retention, for ledger recomputation. Retained raw acquisition facts can repair sample repeat/clock validity without changing the sample's historical mapping or decoded values. Unsupported historical buckets retain their values and obsolete-version/outside-retention provenance rather than acquiring invented coverage. Migration `0005_soc_coverage` adds a nullable column with no fabricated backfill from battery coverage or SOC extrema.

`EnergyInterval.mappingVersion` is representative provenance, not an instruction to apply one mapping to every input: it uses the last original observation strictly before the bucket end (including the seed), or the first future observation only when no predecessor exists. Each sample's own mapping still selects its battery-power source. A bucket spanning a mapping transition can therefore contain inputs normalized under more than one version without its metadata changing merely because recovery replay widened.
